# drafts —— 手写的稿子放这里

这个目录里的每一个文件是**一天的一批新闻**，由对话里写好之后提交进来。
往 `main` 推一份，`.github/workflows/publish.yml` 会自动把它发上站；
也可以在 Actions → 发稿 → Run workflow 手动挑一份。

**这条路一分钱不花。** 花钱的是模型：搜索、读原文、成稿。那几步在对话里做完了，
这里剩下的只有校验、取配图、写数据库——纯脚本，没有模型。

## 格式

一条一块。字段名认不出来的行会被忽略，所以中间加注释没关系。

```
===ITEM 1===
HEADLINE: 主标题
SUBHEAD: 副标题，一句话（可省）
TOPICS: sexual, rights
REGIONS: cn
DATE: 2026-09-09
IMAGE: https://…            留空就去第一个来源的页面取 og:image
NOTICE: 本文含性暴力描述     给读者的内容提示（可省）
LINKS:
- 澎湃新闻 | https://www.thepaper.cn/… | 2026-09-08 | 原报道标题
- 路透社 | https://www.reuters.com/…
BULLETS:
- 要点一
- 要点二
SUMMARY:
正文第一段。

正文第二段。换行就是换行，不用转义。
===END 1===
```

`TOPICS` / `REGIONS` 的可选值见 `scripts/taxonomy.mjs`。

## 发出去之前会被拦住的几件事

1. **来源少于两个**——站长定的规矩，读者要能自己去核。真的只有一家报道过，
   跑的时候加 `--allow-single`，那是一个需要每次单独决定的例外，不是默认。
2. **来源打不开**——每个网址都会被真的点一遍。誊错一个字符，读者点开就是 404。
   （403 / 429 只提醒不拦：那多半是对方挡爬虫，人在浏览器里点得开。）
3. **正文里有本站自述**——「PRISM 将持续关注该案后续」这类句子。这个站不派记者、
   不打电话、不去旁听，写出来就是一句白纸黑字的假话。
4. **正文里有 `[1]` 角标**——出处要在句子里点名：「据《卫报》报道」。
5. **正文短于 400 字或长于 3000 字**。

一条不合格就**整份退回**，一个字都不写进数据库。稿子还在手边，改一行重跑很便宜。

## 本地先看一眼

```
node scripts/publish.mjs --dry drafts/2026-09-09.txt            # 校验 + 点链接
node scripts/publish.mjs --dry --offline drafts/2026-09-09.txt  # 完全不联网
```
